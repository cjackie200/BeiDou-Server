# 生命之证任务链实现说明

本文是当前服务端实现口径，后续修改生命之证任务、奖励、WZ 和补丁包时以本文为准。

## 总体规则

- 系列名称：生命之证。
- 开放条件：120 级及以上、四转冒险家。
- 领取入口：每个任务都通过本职业一转教官领取。
- 提交入口：T1 拜访教官任务到目标教官提交，其余任务回本职业一转教官提交。
- 表现：使用原生任务灯泡、打开的书、闭合的书，不再通过 NPC 其他入口挂旧菜单。
- 任务列表归类：所有可见任务的 `QuestInfo.parent` 按阶段和职业分组，例如
  `生命之证 I：法师`。不要把全部任务挂到同一个 `生命之证` parent 下，旧客户端任务窗口
  可能无法安全处理单组过多任务。
- 客户端任务窗口兼容：`QuestInfo.order` 只能使用小范围排序值，生命之证按槽位写
  `1..21`，禁止写入 `31100` 这类大排序值，避免客户端任务窗口崩溃。
- 阶段：I 到 VII，对应等级 120、130、140、150、160、170、180。
- 奖励：不发血量戒指，直接保底写入 `maxhp/maxmp`，并回满当前 HP/MP。
- 路线锁定：首次领取任意阶段奖励后，锁定生命之证路线，禁止 AP 操作 HP/MP。
- 放弃任务：30100..30999 全部禁止放弃，避免破坏线性任务状态。

## 职业和 ID

任务 ID 预留范围是 `30100..30999`。

```text
blockSize = 25
jobOrder = 战士, 法师, 弓箭手, 飞侠, 海盗
blockBase = 30100 + (((stage - 1) * 5 + jobIndex) * 25)
```

每个职业每个阶段占 25 个 ID：

```text
base+0..8   主线任务
base+9..11  附加试炼选择任务
base+12..19 8 个具体附加试炼
base+20     阶段奖励任务
base+21..23 隐藏桥接任务
base+24     保留锁定任务
```

职业配置：

```text
战士: 112/122/132, 一转教官 1022000
法师: 212/222/232, 一转教官 1032001
弓箭手: 312/322, 一转教官 1012100
飞侠: 412/422, 一转教官 1052001
海盗: 512/522, 一转教官 1090000
```

T1 拜访一转教官时，自己的教官排在最后。例如战士顺序是赫丽娜、汉斯、达克鲁、凯琳、武术教练。

## 线性流程

每个阶段都是完整线性链：

1. 按顺序完成公共主线。
2. 按顺序完成职业主线。
3. 领取第 1 个附加试炼选择任务。
4. 从 8 个附加试炼中选择 1 个，脚本完成 selector，并强制开启具体附加任务。
5. 完成具体附加任务后，服务端静默完成隐藏桥 `base+21`。
6. 第 2 个 selector 通过 `base+21` 解锁，第 3 个 selector 通过 `base+22` 解锁。
7. 完成第 3 个具体附加任务后，服务端静默完成 `base+23`。
8. 奖励任务 `base+20` 通过 `base+23` 解锁。
9. 领取奖励后，下一阶段第一个任务通过上一阶段奖励任务完成状态解锁。

具体附加任务 `base+12..19` 的开始条件依赖保留任务 `base+24` 完成。该保留任务永不完成，因此具体附加任务不会提前出现在可领取列表中，只能通过 selector 脚本强制开启。

隐藏桥 `base+21..23` 只写 `Check.img`，不写 `QuestInfo.img` 和 `Act.img`，不会在任务列表显示。

## 任务数据来源

阶段数值、公共主线、职业主线和 8 选 3 内容继续以 `HpChallengeService.buildStages()` 为唯一来源。

`LifeProofQuest` 负责把旧阶段配置转换为原生任务元数据：

- `KILL` 和 `BOSS` 写入 WZ `mob` 完成条件。
- 多目标击杀或 Boss 目标表示“任意一种”，服务端在击杀 hook 中同步其他目标 mob 的进度，避免原生 WZ 把多个 mob 当成全部要求。
- `MESO` 写入 WZ `money` 完成条件，并由脚本扣除金币。
- `PQ_ANY`、`PQ_PIRATE`、`PQ_TOY_OR_PIRATE`、`SCROLL_100`、`JUMP_MANUAL` 使用自定义进度，达成后发放 `4033011 试炼完成印记`，完成任务时扣除。
- 原 `MAP` 类型全部替换为收集任务。

## 文件落点

- Java 服务：`gms-server/src/main/java/org/gms/server/hpchallenge/LifeProofQuest.java`
- 旧奖励和 AP 锁定：`HpChallengeService`
- Quest fallback：`QuestScriptManager`
- 禁止放弃：`QuestActionHandler`
- 动态掉落：`MapleMap.dropFromMonster`
- 任务脚本：`gms-server/scripts/quest/lifeProof.js` 和 `scripts-zh-CN/quest/lifeProof.js`
- 任务 WZ：`gms-server/wz/Quest.wz` 和 `wz-zh-CN/Quest.wz`

## 验收要点

- GM 辅助：`!hpchallenge status [角色]` 显示当前原生任务状态；`!hpchallenge next [角色]`
  补齐当前任务的击杀进度、收集物、金币或自定义证明，用于快速走完整条任务链。
- 点击一转教官时，不应出现旧的“生命之证 -> 生命之证”菜单嵌套。
- 任务窗口只显示当前可领取、进行中、已完成任务，不应一次显示全部阶段。
- T1 第一个任务只显示本职业块的第一个拜访任务。
- 完成每一步后，下一个任务才出现灯泡。
- 附加试炼 selector 每次只开放一个，选中后具体附加试炼变为进行中。
- 完成一个附加试炼后，下一 selector 才出现。
- 完成第三个附加试炼后，阶段奖励任务才出现。
- 收集物掉落只在对应任务进行中出现，且达到需求后不再追加动态掉落。
- PQ、100% 卷轴和人工跳跳任务完成后，角色获得 `4033011`。
- 领奖后 `maxhp/maxmp` 保底到阶段目标，当前 HP/MP 回满，并写入奖励日志。
