# 生命之证任务与奖励方案

> 当前代码实现以 `docs/life-proof-quest-chain.md` 为准。
> 本文件保留前期数值、阶段和职业任务讨论记录，部分入口、地图访问和实现细节已经被原生任务链方案替代。

本文记录生命之证的完整设计口径。服务端代码、SQL、任务 WZ、任务脚本和基础测试按原生任务链方案落地。

## 审查结论

- 方案可以进入实现阶段。
- 本方案不使用血量戒指，奖励直接修改角色 `maxhp` 和 `maxmp`。
- 玩家必须达到 120 级并完成四转后，才可以通过本职业一转教官开启生命之证。
- 阶段压缩为 T1 到 T7，对应等级 120、130、140、150、160、170、180。
- 180 级最终血量和蓝量目标与参考资料中的 T9 保持一致。
- 缴纳金币类挑战已经全部按参考数值乘以 10。
- 主线采用半差异化结构：公共阶段核心加职业主线分支。
- 原独立职业试炼内容并入职业主线分支，不再作为单独模块展示。
- 菜单、NPC 对话、提示、日志可见文案和玩家可见文案统一使用“生命之证”，不得出现项目品牌词。
- 内部命名统一使用 `hp_challenge` 前缀，不使用项目品牌词。

## 全局规则

### 开启条件

- 角色等级必须大于等于 120。
- 角色必须是四转冒险家职业。
- 入口 NPC 是当前职业对应的一转教官。
- 只允许在一转教官处查看、接取、提交和领奖。
- 未满足条件时，NPC 只显示未开放原因，不创建进度。

### 不开放职业

- 新手。
- 未四转职业。

- 战神。
- 龙神。
- 其他特殊职业。
- GM 普通流程。

### 阶段结构

- 阶段必须按 T1 到 T7 顺序完成。
- 高等级玩家可以连续补做低阶段，不设置每日限制。
- 每个阶段包含：
  - 公共阶段核心。
  - 职业主线分支。
  - 8 选 3 附加挑战。
- 公共阶段核心约占主线强度 35% 到 45%。
- 职业主线分支约占主线强度 55% 到 65%。
- 海盗职业主线统一使用一套海盗分支，奖励仍按拳手系和枪手系区分。
- 8 选 3 保持公共，不做职业差异化。
- 8 选 3 按第 1 项、第 2 项、第 3 项线性选择；每次只能选择 1 个附加挑战，完成后才开放下一次选择。
- 未选择前发生的击杀、Boss、组队任务、访问地图、金币缴纳和消耗行为不追溯。
- 所有任务按当前步骤线性推进，未解锁任务不提前计数。
- 每阶段领取奖励后才解锁下一阶段。

### 计数规则

- 怪物击杀计数：玩家必须在怪物死亡时与怪物处于同一地图，并且对该怪物造成过伤害。
- Boss 参与击杀计数：玩家必须在 Boss 死亡时与 Boss 处于同一地图，并且对 Boss 造成过伤害。
- 组队任务计数：只在组队任务成功结算时计数。
- 地图访问计数：进入指定地图时计数，同一阶段同一地图只计一次，除非任务明确要求次数。
- 跳跳任务计数：通过现有可判定的完成事件计数；无法稳定判定的跳跳内容不得进入首版强制项。
- 金币缴纳：选择对应附加挑战后一次性扣除，扣除成功才完成该项。
- 道具消耗：选择对应附加挑战后扣除，扣除成功才完成该项。
- 所有计数只对当前阶段生效，不跨阶段共享。

### 路线锁定

- 传统洗血和生命之证互斥。
- 角色首次领取生命之证任意阶段奖励时，锁定为生命之证路线。
- 锁定后禁止通过能力值重置券把属性点移入或移出 HP/MP。
- 锁定后禁止手动把升级能力值加到 HP/MP。
- 锁定后禁止自动分配把能力值加到 HP/MP。
- 已经传统洗血且当前 `maxhp` 或 `maxmp` 高于阶段目标的角色，可以完成挑战任务，但奖励只补到阶段目标，不额外增加。
- 奖励计算使用“保底到目标值”，不是“固定增加差值”。

### 奖励写入

奖励领取时直接写入角色基础血量和蓝量：

```text
newMaxHp = min(30000, max(currentMaxHp, targetMaxHp))
newMaxMp = min(30000, max(currentMaxMp, targetMaxMp))
hp = newMaxHp
mp = newMaxMp
```

- 非法师职业不设置阶段目标 MP，`targetMaxMp` 使用当前 `maxmp`。
- 法师职业同时设置 HP 和 MP 阶段目标。
- 领取奖励后当前 HP 和 MP 直接回满到新的上限。
- 每次奖励领取必须写入奖励日志。
- 重复领取同一阶段奖励必须被拒绝。
- GM 回滚必须只能回滚有奖励日志的记录。

## NPC 菜单与文案规则

### 主菜单

NPC 主菜单只展示与当前角色状态相关的入口：

```text

查看规则说明
```

### 文案要求

- 所有可见文案只使用“生命之证”。
- 不出现项目品牌词。
- 不把“洗血路线锁定”写得含糊，必须明确告知玩家领取奖励后不能再通过 AP 操作洗 HP/MP。
- 金币和道具消耗在确认前必须二次提示。
- 奖励领取前必须展示当前上限、目标上限和领取后上限。
- 已高于目标值时必须提示“当前上限已高于本阶段目标，本阶段不会额外增加该项上限”。
- 海盗角色查看奖励时必须明确显示当前角色按拳手系或枪手系计算的目标血量。

## GM 工具

首版实现必须包含 GM 工具，否则线上问题难以处理。

### 必需能力

- 查看角色生命之证总状态。
- 查看当前阶段公共阶段核心进度。
- 查看当前阶段职业主线分支进度。
- 查看已选择的 8 选 3 附加挑战和进度。
- 补齐指定任务目标。
- 一键补齐当前 active 任务，用于开发和联调验收。
- 重置指定阶段进度。
- 回滚最近一次奖励。
- 重置角色生命之证路线锁定。
- 输出角色可读审计日志。

### 快速验收命令

开发和联调阶段不需要真实刷完几百个怪物。GM 可以用以下命令按线性流程推进：

```text
!hpchallenge status [角色]
!hpchallenge next [角色]
!hpchallenge complete <角色> <阶段> <main_common|main_job|optional> <task_key>
!hpchallenge reset <角色> <阶段>
!hpchallenge rollback <角色>
!hpchallenge unlock <角色>
```

- `status` 查看当前任务、已完成记录和当前阶段。
- `next` 直接补齐当前 `active` 任务，并自动解锁下一步。
- 当前处于“选择第 1/2/3 个附加挑战”时，`next` 不会自动选择附加挑战；需要先通过导师菜单选择一个附加挑战，再用 `next` 补齐该附加挑战。
- 金币挑战真实验收时建议走导师菜单缴纳，快速流程可以用 `next` 直接补齐当前金币挑战。
- `reset` 可以清空指定阶段进度，用于重新验收线性顺序。

推荐验收流程：

```text
1 使用测试角色从本职业一转教官开启生命之证。
2 用 !hpchallenge status 查看当前任务。
3 对 NPC 拜访任务，优先实际点击对应导师确认对话触发。
4 对击杀、Boss、组队、地图、卷轴等高成本任务，使用 !hpchallenge next [角色] 快速补齐。
5 到附加挑战选择节点时，在导师菜单选择第 1 个附加挑战，再用 next 补齐。
6 重复选择和补齐第 2、第 3 个附加挑战。
7 三个附加挑战完成后，在导师菜单领取阶段奖励。
```

### 回滚规则

- 只能回滚存在 `hp_challenge_reward_log` 的奖励。
- 回滚时恢复奖励前的 `maxhp`、`maxmp`、`hp` 和 `mp`。
- 回滚必须写入 GM 操作日志。
- 回滚后该阶段奖励状态恢复为未领取。
- 如果后续阶段已经领取，禁止直接回滚中间阶段，必须从最高阶段开始逐级回滚。

## 数据设计

### `hp_challenge_state`

用于记录角色总体路线和阶段状态。

```text
id
character_id
route_locked
current_stage
highest_rewarded_stage
status
created_at
updated_at
```

建议约束：

- `character_id` 唯一。
- `route_locked` 默认 false。
- `highest_rewarded_stage` 默认 0。
- `current_stage` 范围 1 到 7。

### `hp_challenge_progress`

用于记录阶段目标进度。

```text
id
character_id
stage
task_group
task_key
target_type
target_id
current_count
required_count
selected
completed
created_at
updated_at
```

说明：

- `task_group` 可取 `main_common`、`main_job`、`optional`。
- `main_common` 表示公共阶段核心。
- `main_job` 表示职业主线分支。
- `optional` 表示 8 选 3 附加挑战。
- 职业分支由角色当前四转职业映射，不单独让玩家选择。
- `selected` 只对 8 选 3 附加挑战有意义。
- 8 选 3 的未选择项不得计数。
- 同一角色、阶段、任务组、任务键必须唯一。

### `hp_challenge_reward_log`

用于记录奖励发放和回滚。

```text
id
character_id
stage
job_id
before_maxhp
before_maxmp
before_hp
before_mp
after_maxhp
after_maxmp
after_hp
after_mp
operator
reverted
reverted_at
created_at
```

说明：

- 玩家正常领取时 `operator` 记录为空或系统值。
- GM 回滚时更新 `reverted` 和 `reverted_at`。
- 同一角色、同一阶段只能存在一条未回滚的奖励记录。

## 实现落点

### 服务端

- 新增 `HpChallengeService`：负责阶段配置、状态查询、阶段解锁和提交判定。
- 新增 `HpChallengeProgressService`：负责击杀、Boss、地图访问、组队任务、消耗项和金币项计数。
- 新增 `HpChallengeRewardService`：负责奖励计算、写入 `maxhp/maxmp`、回满当前 HP/MP、写奖励日志。
- 新增 `HpChallengeGmService`：负责 GM 查询、补齐、重置和回滚。
- 新增 Flyway migration，创建生命之证相关表。
- 在 AP 分配和 AP 重置流程加入路线锁定校验。
- 在怪物死亡或伤害贡献链路加入生命之证计数。
- 在组队任务成功结算链路加入生命之证计数。
- 在地图切换链路加入地图访问计数。
- 在任务配置中把公共阶段核心、职业主线分支和 8 选 3 分开建模。

### 配置形式

阶段配置建议在 Java 中集中定义，首版不需要做成后台可编辑配置。

原因：

- 首版需要保证任务口径稳定。
- 阶段目标会参与服务端判定，不应被误操作动态修改。
- 后续如果需要活动化或后台调整，再迁移为数据库配置。

## 资源与 ID 核验

实现前必须用当前服务端 WZ 和客户端 WZ 核验以下内容：

- NPC ID 是否与一转教官一致。
- 怪物 ID 是否存在。
- 地图 ID 是否存在。
- Boss 死亡 ID 是否与实际击杀结算 ID 一致。
- 组队任务成功事件是否有稳定落点。
- 跳跳任务是否有稳定完成事件。
- 100% 卷轴是否能用现有道具分类可靠判断。

如果某个怪物、地图或事件无法稳定判定，不能静默替换，必须先调整方案并记录原因。

## 验收标准

### 基础流程

- 119 级四转角色不能开启。
- 120 级未四转角色不能开启。
- 120 级四转冒险家可以开启。
- 非开放职业不能开启。
- 每个职业进入正确的一转教官入口。
- 每个职业加载正确的职业主线分支。
- 海盗职业加载统一海盗主线分支。
- T1 到 T7 必须按顺序完成。
- 高等级角色可以连续补做多个阶段。

### 计数流程

- 公共阶段核心和职业主线分支都完成后，才允许提交阶段主线。
- 未选择的 8 选 3 项不计数。
- 选择后的 8 选 3 项从 0 开始计数。
- 同地图但未造成伤害不计 Boss 和怪物击杀。
- 造成伤害但死亡时不在同地图不计 Boss 和怪物击杀。
- 同地图且造成伤害才计 Boss 和怪物击杀。
- 组队任务失败不计数。
- 组队任务成功才计数。
- 地图访问同一阶段按规则计数，不重复刷同一节点。

### 奖励流程

- 每阶段奖励只能领取一次。
- 领取后直接更新 `maxhp` 和 `maxmp`。
- 领取后当前 HP 和 MP 回满。
- 当前上限高于目标值时不额外增加。
- 上限不得超过 30000。
- 法师同时补 HP 和 MP。
- 非法师只补 HP。
- 拳手系海盗走拳手 HP。
- 枪手系海盗走其他职业 HP。
- 海盗任务统一不影响拳手系和枪手系的奖励分流。

### 路线锁定

- 领取首个阶段奖励后路线锁定。
- 锁定后 AP Reset 不能移入 HP。
- 锁定后 AP Reset 不能移出 HP。
- 锁定后 AP Reset 不能移入 MP。
- 锁定后 AP Reset 不能移出 MP。
- 锁定后手动加点不能加 HP/MP。
- 锁定后自动分配不能加 HP/MP。
- 普通 STR、DEX、INT、LUK 加点不受影响。

### GM 工具

- GM 可以查看总状态。
- GM 可以查看公共阶段核心进度。
- GM 可以查看职业主线分支进度。
- GM 可以查看 8 选 3 进度。
- GM 可以补齐指定目标。
- GM 可以一键补齐当前 active 任务。
- GM 可以重置指定阶段。
- GM 可以回滚最近一次奖励。
- GM 不能跳过后续阶段直接回滚中间阶段。
- 所有 GM 修改都有日志。

## 已知待实现风险

- 部分 Boss 的实际死亡怪物 ID 可能与展示怪物 ID 不一致，实施前必须以 WZ 和现有 Boss 脚本核验。
- 跳跳任务完成事件可能不统一，首版如果不能稳定判定，应把跳跳项替换为可判定任务。
- 任意组队任务和指定组队任务需要确认现有事件脚本是否有统一成功回调。
- 100% 卷轴需要确认道具分类是否可靠，否则应改为指定卷轴清单。
- 地图访问类挑战需要避免玩家反复切图刷同一地图。
- GM 回滚直接修改角色血蓝上限，必须和角色在线状态、保存流程、客户端刷新保持一致。
