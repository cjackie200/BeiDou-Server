# 背包栏位与物品堆叠策略

当前普通背包栏位策略是不突破客户端稳定上限，只把默认值补到最大值。

- 新建角色的 `EQUIP`、`USE`、`SETUP`、`ETC` 初始栏位为 96。
- `CASH` 背包固定按 96 返回。
- 商城扩展券、GM 调整或其他扩展入口仍不能把普通背包扩到 96 以上。
- Flyway `V1.11.12__set_default_inventory_slots_96.sql` 会把旧角色普通背包栏位统一校正为 96，并把 `characters` 表对应字段默认值改为 96。
- 执行该迁移时应停服，避免在线角色在迁移后又保存旧栏位值。

本策略不包含突破 96。若后续需要超过 96，必须先验证客户端背包 UI、物品栏协议、槽位序列化和所有扩展入口是否支持更大值。

## 物品堆叠

当前物品堆叠策略是不修改物品数量协议和 Java 类型，只把全局配置调到安全值。

- `game_config.item_slot_max` 配置为 30000。
- 该配置只覆盖 `USE` 和 `ETC` 背包类型；装备仍按 1 个一格处理。
- 物品数量当前在 `Item.quantity`、背包操作和多数发包中仍使用 `short`。
- 飞镖和子弹会按熟练度额外增加堆叠上限，因此不应把全局配置贴近 `32767`。
- Flyway `V1.11.13__set_item_slot_max_30000.sql` 会把已有配置更新为 30000；若配置缺失，会补插入该配置。

本策略不包含突破 `short` 上限。若后续需要超过 30000 或超过 32767，必须同步改服务端数量类型、背包/仓库/交易/商店/掉落/后台管理读写、协议序列化和客户端显示逻辑。
