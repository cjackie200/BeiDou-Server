# 任务完整性与资源一致性

## 权威数据边界

- `Check.img` 决定任务能否开始或完成；服务端缺少对应顶层节点时，原生 `start/complete`
  必须 fail-closed。只有明确的内部状态机可以调用 `forceStart/forceComplete`。
- `Act.img` 是物品、金币、经验、声望、技能、宠物技能和任务状态动作的唯一执行源。脚本不得重复
  发放或扣除同一奖励。
- `QuestInfo.img`、`Say.img` 只承载客户端展示和原生对话；它们不能替代服务端条件判断。
- `autoStart`、`autoPreComplete`、`autoComplete` 是客户端入口/展示元数据，不能绕过服务端
  `canStart/canComplete`。

服务端已显式支持中文服 `Check.img` 中使用的等级、职业、前置任务、物品、怪物、金币、声望、
技能、怪物卡、骑宠等级、穿戴装备、变身、宠物召回/自动说话、开始/结束时间、世界范围、每日任务等
条件。新增字段若没有服务端语义，不得静默忽略：必须实现、fail-closed，或同时从服务端和客户端资源
移除入口。

`infoex` 的 `cond=0/1/2` 分别表示字符串精确相等、数值大于等于、数值小于等于；阈值条件的
实际进度或期望值无法解析为整数时必须 fail-closed。

`30006..30009` 为分阶段技能突破任务，分别对应一至四转。任务只在当前职业对应阶段存在突破
技能时出现；空阶段自动跳过。目标依次为木妖王 3 只、树妖王 3 只、肯德熊 3 只和扎昆最终
本体 1 只。每阶段只解锁该转技能并发放对应 SP，服务端加点门禁以阶段任务完成状态为准。

旧版 `30006` 已完成角色迁移为全阶段完成；旧版进行中角色迁移到 `30009` 并保留扎昆进度，
通过内部 `legacy-all` 进度标记在完成时一次性结算原版全部阶段奖励。该标记不得出现在客户端
QuestInfo 文本中。

## 动作执行约束

- 所有动作先完成检查，再更新任务状态和执行奖励；背包空间不足、金币不足/溢出或选择非法时，任务
  保持原状态且不得部分扣除或发放。
- 正金币奖励按实际任务倍率计算后再检查 `Integer.MAX_VALUE`；负金币不乘倍率。
- 重复的负物品动作按物品 ID 汇总检查；装备可由 `EQUIP` 与 `EQUIPPED` 合计满足，并按实际位置
  删除。
- `prop=-1` 只表示玩家选择项，`prop>0` 表示随机权重，`prop<-1` 拒绝执行；数量为 0 的历史脏
  动作跳过。
- 宠物任务技能 `128/256` 分别写入宠物属性 `0x80/0x100` 并持久化到 `pets.flag`。多宠物角色
  必须使用当前任务 `pet` 条件实际匹配的宠物；技能、亲密度、速度和属性上限检查不得固定写入
  pet slot 0。

## 当前禁用的不可执行任务

下列任务同时从中文服务端 `Quest.wz` 和客户端 `Data/Quest` 的 `QuestInfo/Check/Act/Say` 移除，
服务端仍保留 ID 拒绝表，防止旧客户端构造请求：

- `4490`：依赖 v83 服务端未实现的 `userInteract` 玩家搜索流程，且 `q4490s/q4490e` 不存在。
- `8510..8515`、`8540..8541`：资源链不完整或为孤立残留。
- `29000`：要求 5 个组队任务 S 评级。服务端已能读取 `area_info` 的 `rank=S`，但当前组队任务
  脚本没有生成评级记录；在评级写入链路完成前不展示该勋章任务，避免错误完成图标或无条件领奖。

重新启用任一任务前，必须同时补齐条件产生端、服务端校验、四个客户端 Quest IMG、四个服务端
Quest XML 和回归测试。

## 验证

- `QuestWzResourceTest` 校验恢复/禁用节点、任务物品标记、关键文本宏以及所有顶层 Check 字段均有
  显式服务端映射。
- `QuestActionRegressionTest` 覆盖缺失 Check、禁用 ID、自动任务元数据、原生物品/金币/声望/技能
  动作和关键任务链。
- `ItemActionTest`、`PetSkillActionTest`、`QuestRequirementRegressionTest` 覆盖动作和条件边界。
- `SkillBreakthroughQuestTest` 覆盖 `30006..30009` 灯泡节点、分阶段怪物进度、突破技能资源、
  职业映射和旧任务迁移。
- 客户端资源用 `WzPatchTool inspect` 逐节点确认，并运行 `ring-verify`、`life-proof-verify`、
  `elemental-resonance-verify`。
